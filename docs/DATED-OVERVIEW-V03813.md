# STREAKFIT v0.38.13 日期图文总览

2026-10-21，基于v0.38.12 / 8b3f7a656e83aa732191f87c227b9985d28f05b9。另存并发布新版本，原版本与原检验脚本保留。

## 证据与范围

1. 原app.js的enhance仅today分支调用illustratedToday；openWorkoutDay把其他日期送到完整记录编辑器，导致用户截图中的无图、长表单。现在未来日期先显示illustratedDatedPlan，显式进入编辑后保留原表单。
2. historicalView原本只有名称和逐组文字；现在复用同一overviewGraphic，配实际历史日志和原编辑/撤销入口。没有历史时不重新生成或编造实际记录。

没有改处方算法、训练排序、XP、数据字段或备份格式。没有生成新图或引入外部素材。已有通用部位图、准备姿势和撤下图仍明确标注，不宣称全部动作都有教学图。

## 验证结果

- 中英文×320/390/1280共6个浏览器场景：未来图文及目标、无记录输入、教学返回原日期、编辑目标仅作用该日并在刷新后保留、历史实际图文及原数据、历史修改与撤销、缺失历史不生成、今天数据隔离、离线图片、无横向溢出、无页面或控制台错误。
- 中英文390px边界：分钟型活动、活动度每侧剂量、撤下图标签、恢复日没有自动动作、空训练日不误标为恢复日、显式编辑后仍能添加、未安全确认不记录。
- 原8个浏览器回归场景：5屏设置，稍后浏览而不能训练，异常/不确定安全拦截，配额保存失败与重试，完成训练30XP/本周1次，刷新保留，JSON备份导出导入一致，离线打开。
- 中英文独立HTML：与网页相同的日期入口、图像内嵌、编辑及历史流程。
- 全部284项非矩阵测试：271通过、13失败、0跳过。原测试、fixture、helper和指标定义逐文件保留，不改断言让其通过。18,144组合矩阵未重跑，当前只改展示和导航。

12项基准既有失败：旧图片审核断言（要求新补图仍占位）、有氧无记录/减量、旧个人资料位置、第四周周期、未来日期周期、未来编辑旧目标、一般状态减组、基于实际记录进展、28日路线、上下肢轻重轮换、肩部预算/减量、今日摘要。完整原名见基准COMMON-ART-V03812.md及测试输出。没有在本轮扩大训练算法范围。

新增1项：`future recovery day explains light activity instead of exposing ineffective specialty controls`。恢复文字和无效专项控件检查通过，其中一条断言要求进入该日期后立即存在data-add-exercise；新流程把它移到明确“调整这天的计划”之后。实际点击添加入口已在中英文浏览器验证；未通过插入隐藏按钮或修改测试规避冲突。

## 未解决风险

- 整套测试仍非全绿，周期/处方方面的既有失败需单独处理，不应仅凭本轮UI回归宣称训练逻辑已全面正确。
- 真实iPhone Safari、人体动作质量和真人设置时间没有验证；Chromium模拟手机不等同真机。
- 现有素材仍有占位和待补图；蓝色人体AI静态图不是动作认证或连续视频。
- 数据仅本机，账号同步未开放，备份未加密；预览版共享本机预览数据，避免同时编辑。
